# 项目审查流程

1. 确认用户目标、已关联项目与允许范围，读取入口和实际调用方。
2. 按状态所有者与提交边界追踪执行，记录实际问题及源码位置。
3. 区分 Ticket 授权、Receipt 效果、Artifact 产物和独立 Verification。
4. 用户要求修改时，使用当前获准工具实施；用户只要求审查时返回证据与建议。
5. 明确缺测、失败及未验证范围，不把静态阅读或模型自述称作测试通过。

此流程不授予新工具、路径、认证或执行权限。是否运行验证由当前用户任务决定。
