# 会话统计

Runtime 第三栏顶部显示当前**整段会话**的四项累计统计；下方 Tokens、Tools、Recovery 等区域仍展示最新 Turn。

| 指标 | 口径 |
|---|---|
| 模型用时 | Runtime 实测模型调用的 wall-clock 毫秒之和，包含认证/网络等待与已知失败，不含等待重连的空闲时间 |
| 工具调用用时 | 已记录工具执行的单调时钟耗时之和，包含结果准备与实际执行，结束于收据发布前；不含恢复等待和收据复用 |
| 首 token 平均（TTFT） | 每次已报告调用从开始到首个非空文本增量的毫秒数，按调用取算术平均；不平均每轮均值 |
| 输出速度（TPS） | **成功调用的可见输出 Token（或明确标记的估计）总量 ÷ 同一批调用的总用时（秒）**，包含 TTFT；不平均单次 TPS |

TPS 只使用有有效输出计量与正耗时的成功调用。失败、UNKNOWN、缺测、零毫秒分辨率的调用不参与速率。这是包含网络/TTFT 的端到端速度，不是 GPU 解码速度。

可见输出采用三级证据：① 明确 Folded/Unfolded 语义得到的精确 `visible_output_tokens`；② 总量有偏差时借鉴 Hindsight 的上下界夹取法计算 `estimated_visible_output_tokens`；③ 历史收据仅有供应商原始 `output_tokens` 时，使用标注来源的代理估算。只要配对样本中有估算，UI 一律显示 `≈` 并在提示中标注估算次数和原始代理次数。该近似指标仅用于展示，不得写回原始供应商计量、执行账本或预算结算。

Token 和耗时不足以构成有效配对时仍显示“未报告”，不得伪造零或凭文本长度假装 Token 真值。部分耗时如 `1.5秒 · 1/3` 表示三次记录中只有一次具备耗时，值仅累计已测部分。空会话模型/工具累计为零，TTFT/TPS 尚无样本。Web 主对话的 Ollama NDJSON 与 GPT / DeepSeek SSE 使用实际非空正文增量测 TTFT；未接入预览的 Ollama 非流式调用继续保持“未报告”。Ollama `prompt_eval_cached_count` 仅在远端实际提供时计入缓存读数。浏览器通过既有会话轮询读取生成预览，预览不是完成消息。

工具收据与 `workspace_operations.tool_wall_ms` 保存同一实测毫秒，结算原子记入；进程在收据发布后退出，可核对原收据恢复，稳定 `decision_id` 复用不重新计时。旧表增量增加可空列，旧记录不从粗粒度时间戳回填。无计量/坏计量不改变效果核对、授权或预算。

会话读取复用已有模型/工具记录做线性汇总，不新增逐轮数据库查询，也不签发调用。页面计量不变时复用已显示的统计，刷新与重启继续读取持久事实。

回归：`tests/test_session_statistics.py` 覆盖加权口径、缺测/坏值、零、重复身份、跨会话与重启、旧表/收据、真实 `os._exit` 和本机 HTTP；`tests/test_statistics_ui.cjs` 验证同一展示实现的单位及覆盖。夹具不证明真实供应商速度。
